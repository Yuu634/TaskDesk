# Orca 連携

TaskDesk のタスクツリーから、Orca に登録済みのプロジェクト・ホスト・ワークツリーを指定して Codex / Claude Code を起動できます。同じリポジトリのローカル作業と SSH サーバー上の作業を、タスクごとに切り替えられます。

## 設定と実行

1. TaskDesk と Orca を同じ PC・OS ユーザーで起動します。SSH 先は Orca で接続し、対象ディレクトリをワークツリーとして登録しておきます。
2. TaskDesk の「ツリー編集」→「実行の既定設定」で、実行先を「Orca の対話 Agent」に変更します。
3. 「Orca から一覧を更新」で、プロジェクト、実行ホスト、ワークツリーを選択して保存します。実行管理はこの PC で動きます。
4. TASK の設定では既定の実行先を継承します。「ツリーの Orca 実行先を継承」を外すと、TASK ごとに別のホスト・ワークツリーを指定できます。
5. AI ツール、モデル、Thinking、Approve を設定し、TASK / WP / ツリーを実行します。各 TASK に専用タブを作り、依存先の結果を含むプロンプトを一度送ります。
6. 「Orca で開く」から承認や追加の会話を行います。Codex の終了通知を回収し、TASK の自動検証を有効にした場合は検証結果からラベルを記録します。未設定なら確認待ちになります。[終了通知と自動完了の設定](notifications.md) を参照してください。「完了」で後続へ進みます（承認必須 TASK は承認待ち）。

例えば `openAI_hackathon` プロジェクトを選び、ローカル作業には `this machine`、リモート作業には `g15` と `/mnt/kiso-qnap5/obara` のワークツリーを選択します。TaskDesk に SSH マシンを二重登録する必要はありません。リポジトリや新しい Git worktree は自動作成しません。

実行先の Orca ターミナルで `node` と選択した AI CLI を利用できることが必要です。CLI のログインや初回の信頼確認は各実行先で行います。「AI ツールの実行パス」は必要な場合だけ指定してください。モデル・MCP・追加ディレクトリ・環境変数も実行先の環境で解釈します。Claude の MCP 設定ファイルは実行先ユーザーの一時ディレクトリに作り、CLI の正常終了時に削除します。

Windows の通常インストール先の `orca.exe` は自動検出します。WSL で TaskDesk を動かす場合も、Windows 相互運用が有効なら同じデスクトップの Windows 版 Orca CLI を検出します。このとき Orca の `local` は Windows を指します。別の配置なら、サーバー起動前に `ORCA_BIN` を設定します（WSL では `/mnt/c/.../orca.exe` も指定できます）。

端末作成には Orca 同梱の `RuntimeClient` と `terminal.create` の `launchAgent` を使用し、Orca に AI の種類を登録します。Orca 1.4.205 で確認しています。同梱モジュールはインストール先から検出し、起動データを標準入力と端末環境変数で渡します。WSL から Windows 版 Orca を操作する場合は Windows 側の `node.exe` も必要です。インストール構成が異なる場合は `ORCA_RPC_CLIENT` で `app.asar.unpacked/out/cli/runtime-client.js` のパスを指定できます。

```powershell
$env:ORCA_BIN = 'C:\path\to\orca.exe'
npm.cmd run restart
```

## 実行の扱い

- 表示名ではなくプロジェクト ID・ホスト ID・ワークツリー identity を照合します。接続切断・削除・再登録時に別の作業先へ自動変更しません。
- 実行ごとに新規タブを作ります。既存のユーザーの会話には送信しません。完了したタブは残します。
- タブ作成・プロンプト送信の前に意図を永続化します。応答が失われた場合は失敗として表示し、自動再送しません。Orca の既存タブを確認してから再実行してください。
- 入力の受付だけでは送信成功とみなしません。Orca が `turn_started` を確認した応答が必要です。未確認時は端末を保持して停止します。
- AI の入力待ち・応答終了だけでは完了にしません。Codex の通知、親セッションとターンの照合、事前設定した完了条件の検証を経て自動確定します。自然言語だけの完了条件は人が確認します。ファイル・Git の変更はホスト間で自動同期しません。
- 「停止」または制限時間超過では、作成した端末のホスト・ワークツリー・incarnation を再照合して、その端末だけを閉じます。切断中など停止を確認できない場合はログを確認し、Orca 側で停止してください。
- Web サーバーを閉じてもワーカーは継続します。Orca とこの PC は起動したままにしてください。Orca の再起動による runtime の変更は中断として扱います。

## 現在の制限

- 接続先はローカルと Orca の SSH ホスト。ペアリングした別の Orca サーバーは対象外です。
- 添付は実行先のパス指定に対応します。アップロード添付の自動転送には未対応で、実行前にエラー表示します。
- プロンプトは親タスクや先行結果を含め 24,000 文字未満。端末制御文字は送信できません。大きな MCP 設定・環境変数も起動前に上限確認します。
- 新規作成の「実行の既定設定」で Orca を選ぶと、指定した Orca ワークツリーで計画を生成し、設定を生成後のツリーへ引き継ぎます。ゴールモードの自動反復と Orca 上での編集案生成には未対応です。
- 他ユーザーが Orca 外で実行した処理や、同じ SSH ホストを別名で登録した通常実行との排他は保証しません。共有作業ディレクトリを使用する場合は利用者間で調整してください。

## 保存と検証

ツリーと TASK の `orca` に `projectId`、`hostId`、`worktreeId`、`identityKey` を保存します。TASK の `orca: null` / 未指定はツリーの設定を継承し、個別設定は丸ごと置き換えます。

`runs/<runId>/input.json` に照合済みの実行先と runtime、`orca/<nodeId>/dispatch.json` に端末 handle・incarnation・送信 receipt、`interactive.json` に現在の対話状態、`transcript.json` に完了時の端末出力を保存します。シークレットを含む MCP・環境変数は従来どおり実行スナップショットに入るため、データディレクトリを公開しないでください。

`npm test` は偽の Orca CLI で経路・継承・送信・停止・同時起動の排他と HTTP / ワーカーの連携を検証します。実際の AI に指示を送らずに実行できます。
