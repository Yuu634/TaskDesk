# 終了通知と分割ペインの完了判定

Orca + Codex の通知回収モードでは、作業終了後に同じタブを分割し、新しい読み取り専用の対話型 Codex で完了条件を判定します。作業用の会話は終了せず残ります。Claude Code・手動記録・直接実行・herdr の方式は変更しません。

## 設定

1. Orca のプロジェクト・ホスト・ワークツリーを選び、Codex の終了通知を回収する設定にします。
2. SSH の場合は同じホスト・OS ユーザーへの接続を TaskDesk に登録し、通知回収用の SSH 接続として対応付けます。
3. TASK の「完了条件」に 1 行につき 1 条件を自然言語で入力します。
4. TASK を実行します。通知経路の往復確認後、プロンプトは Codex の起動引数として一度だけ渡します。
5. 作業終了通知とターンを照合し、判定用ペインを追加します。初回の判定結果を回収してラベルを付与します。

専用スクリプトは不要です。必要なら「完了条件の自動検証（補助・任意）」で検証プログラム・引数の JSON 配列・制限時間を設定し、補助検証を有効にします。例：プログラム node、引数 ["scripts/verify-task.cjs"]。シェルの && やリダイレクトは解釈しません。実行先ユーザーの権限で動くため、確認済みのプログラムを指定してください。

## 判定と再判定

- 全条件に達成の根拠があれば「完了」です。
- 未達・判断不能・条件未設定・不正な回答・起動や接続の失敗・時間超過は「要確認」です。
- 補助検証が失敗した場合は AI の判断にかかわらず「要確認」です。
- 「要確認」は後続 TASK を止めます。人が完了を承認するか、作業側で修正後に「完了条件を再判定」を押します。
- 判定中に作業側で新しいターンが始まった場合は判定を無効にします。外部エディターなどからの変更をすべて検出する仕組みではありません。
- 判定ペインには追加質問できます。追加会話だけでは記録済みラベルは変更しません。
- 再判定は作業を再実行せず、作業ペインの直近の終了ターンに対して新しい判定ペインを作成します。確認待ちでは同じ実行内で、終了済みでは新しい履歴に保存します。ツリー編集後は TASK を再実行してください。
- 承認必須の TASK は、AI 判定が完了でも人の承認を待ちます。

判定にも AI の利用枠を使用します。判定用 Codex は読み取り専用・承認なしで起動し、Web 検索・Apps・MCP・子エージェントを無効にします。作業指示・完了条件・最終回答・補助検証結果を評価対象データとして渡し、各条件の met / unmet / unknown と根拠を JSON で返させます。構造・条件数・根拠を検査します。修正やテスト実行は指示しません。

## 識別と保存

作業と判定には別々の通知ディレクトリ・トークン・セッション ID を割り当てます。実行先の ~/.taskdesk/notifications/ 以下に通知を保存し、TaskDesk 側に作業結果・判定結果・ペイン情報を保存します。既存の通知先は引き継ぎ、恒久設定は変更しません。

終了通知は完了を意味しません。該当 thread-id の保存イベントから CLI / user セッションと turn-id を照合し、子セッションを除外します。形式変更・記録なし・曖昧な識別・32 MB 超のセッション記録では自動確定しません。分割の応答が失われてもペインを二重作成せず「要確認」にします。判定終了後は両ペインを残します。

更新前の TASK の方式は変更しません。新しい実行から分割方式を適用します。WSL → Windows 版 Orca / Codex 0.155.1 で対話型判定と自動完了を確認しました。SSH 実機は未検証です。
