# 終了通知と分割ペインの完了判定

Orca + Codex の通知回収モードでは、作業終了後に同じタブを分割し、新しい読み取り専用の対話型 Codex で完了条件を判定します。作業用の会話は終了せず残ります。Claude Code・手動記録・直接実行・herdr の方式は変更しません。

## 設定

1. Orca のプロジェクト・ホスト・ワークツリーを選び、Codex の終了通知を回収する設定にします。
2. SSH の場合は同じホスト・OS ユーザーへの接続を TaskDesk に登録し、通知回収用の SSH 接続として対応付けます。
3. TASK の「完了条件」に 1 行につき 1 条件を自然言語で入力します。
4. TASK を実行します。通知経路の往復確認後、プロンプトは Codex の起動引数として一度だけ渡します。
5. 作業終了通知とターンを照合し、判定用ペインを追加します。初回の判定結果を回収してラベルを付与します。

専用スクリプトは不要です。必要なら「完了条件の自動検証（補助・任意）」で検証プログラム・引数の JSON 配列・制限時間を設定し、補助検証を有効にします。例：プログラム node、引数 ["scripts/verify-task.cjs"]。シェルの && やリダイレクトは解釈しません。実行先ユーザーの権限で動くため、確認済みのプログラムを指定してください。

## 起動時のプロンプトと開始確認

Codex・Claude Code とも、手動通知モードを含めて最初のプロンプトを起動引数で一度だけ渡します。起動後に端末へプロンプトを打ち込む処理は行いません。大きすぎるプロンプトはタブ作成前に拒否します。

「送信済み」は起動要求にプロンプトを含めた状態です。プロセスの起動通知だけでは AI の実行開始と判断しません。送信したプロンプトに一致する親セッションのターンを通知から照合できた時点で「実行開始を確認」とします。この確認は応答終了後になる場合があります。

手動通知モードの Codex は、Orca の対象端末の現在画面を読み取って進捗を補います。読み取りの前後で端末・実行先・AI ツールの同一性を照合し、Codex の作業表示、または回答・処理時間・入力欄の組み合わせを確認します。単なる CLI 起動、出力の増加、過去の蓄積ログだけでは開始済みと判定しません。応答終了と入力待ちを確認できた TASK は、画面にある結果を保存し「要確認」に移行します。以降の承認待ち時間には実行の制限時間を適用しません。画面は全文でない場合があり、完了条件の合格を証明するものではありません。実行結果タブで内容を確認し、完了を承認してください。表示形式が未対応なら未確認を維持します。

旧バージョンでタイムアウトした最新の TASK も、同じ端末の応答終了と入力待ちを確認できれば、再送せず確認待ちに復元します。ツリーの編集後・再実行後・端末の置き換え後・実際の CLI エラーは復元対象外です。元の状態は before-timeout-recovery.json に保存します。復元結果の承認後、未実行の TASK が残っている場合は「次TASKを実行」で続行してください。

60 秒経過しても確認できない場合は「プロンプト送信済み・AI の実行開始は未確認」と表示し、既存の Orca タブの確認を促します。自動再送・タブの再作成は行いません。入力待ちを確認できる場合は、ユーザーがタブの結果を確認して手動記録できます。開始未確認の会話は制限時間経過でも閉じず、明示的な停止時のみ対象端末の同一性を確認して停止します。

## 判定と再判定

実行結果タブ下部の「完了判定」では、「完了」「要確認」「エラー」「想定外」を自分で選び、任意の判定メモとともに保存できます。AIの判定・実行結果は書き換えず、人によるラベルと変更履歴を別に保存します。要確認は承認待ち、エラー・想定外は後続停止、完了は次TASKへ進める状態です。更新前から確認待ちだった実行は、待機ワーカーを終了して保存し、残りは「次TASKを実行」で続けられます。

ツリー上部の「設定編集」で、完了後の進行を「自分で確認」または「AI判断で自動」に切り替えます。自動進行は選択した実行範囲内に限られ、要確認・エラーでは止まります。手動設定ではAIの判定が合格でも人の承認を待ちます。手動記録モードでは自動合格判定を行いません。

TASKの実行結果タブ下部に「タスク追加」「完了判定」を配置しています。「完了判定」から人による承認、または最新報告の取得とAI判定を行います。条件の編集はTASKの設定で行います。実行範囲内で待機しているTASKには「実行予定」が付きます。ツリー編集の「AIで編集」は、Orca利用時も対象範囲とプロンプトを指定してバックグラウンドで編集案を生成し、確認後に適用できます。

「要確認」から修正する場合は、実行結果タブの「Orcaで修正する」で元の作業ペインを開き、そこで修正を指示します。以前の結果は「修正前」として扱います。修正終了後に画面下部の「完了判定」から「最新結果を取得して判定」を押すと、同じ作業ペインに更新版の結果報告を依頼します。その依頼への新しい応答だけを採用し、既存の判定ペインへ渡します。判定ペインが置き換わっている・作業中・送信の確認が取れない場合は自動再送せず、要確認を維持します。

修正前の報告・判定は履歴に残し、最新結果に置き換えます。通知回収を使わない手動記録モードでは、識別付きの更新版報告を画面から回収し、条件の自動合格判定はせず、人の確認を待ちます。画面から全文を取得できない場合があります。要確認中に作業の再開・結果の変更を検出した場合も、修正前の結果で完了を確定しません。

完了結果は TASK 単位で実行時の設定と照合します。別 TASK の追加・編集や並べ替えだけでは、変更していない TASK の完了は無効になりません。「次TASKを実行」「次WPを実行」は有効な完了結果を引き継ぎます。対象 TASK のプロンプト・完了条件・実行先・親の指示・依存 TASK の内容などが変更された場合は、過去の結果として表示し再実行の対象にします。要確認の結果が残っている間は、次の TASK を選びません。個別の再実行ボタンは、完了済み TASK の明示的な再実行にも使えます。

- 全条件に達成の根拠があれば「完了」です。
- 未達・判断不能・条件未設定・不正な回答・起動や接続の失敗・時間超過は「要確認」です。
- 補助検証が失敗した場合は AI の判断にかかわらず「要確認」です。
- 「要確認」は後続 TASK を止めます。人が完了を承認するか、作業側で修正後に「完了条件を再判定」を押します。
- 判定中に作業側で新しいターンが始まった場合は判定を無効にします。外部エディターなどからの変更をすべて検出する仕組みではありません。
- 判定ペインには追加質問できます。追加会話だけでは記録済みラベルは変更しません。
- 再判定は作業を再実行せず、作業ペインの直近の終了ターンに対して新しい判定ペインを作成します。確認待ちでは同じ実行内で、終了済みでは新しい履歴に保存します。ツリー編集後は TASK を再実行してください。
- 承認必須の TASK は、AI 判定が完了でも人の承認を待ちます。

判定にも AI の利用枠を使用します。判定用 Codex は読み取り専用・承認なしで起動し、Web 検索・Apps・MCP・子エージェントを無効にします。作業指示・完了条件・最終回答・補助検証結果を評価対象データとして渡し、各条件の met / unmet / unknown と根拠を JSON で返させます。構造・条件数・根拠を検査します。修正やテスト実行は指示しません。

## 識別と保存

作業と判定には別々の通知ディレクトリ・トークン・セッション ID を割り当てます。実行先の ~/.taskdesk/notifications/ 以下に通知を保存し、TaskDesk 側に作業結果・判定結果・ペイン情報を保存します。既存の通知先は引き継ぎ、恒久設定は変更しません。

終了通知は完了を意味しません。該当 thread-id の保存イベントから CLI / user セッションと turn-id を照合し、子セッションを除外します。形式変更・記録なし・曖昧な識別・32 MB 超のセッション記録では自動確定しません。分割の応答が失われてもペインを二重作成せず「要確認」にします。判定終了後は両ペインを残します。

更新前の TASK の方式は変更しません。新しい実行から分割方式を適用します。WSL → Windows 版 Orca / Codex 0.155.1 で対話型判定と自動完了を確認しました。SSH 実機は未検証です。
# Orcaの既存接続による判定（v0.7.16）

Codexで「AI判断で次TASKへ自動で進む」を選ぶと、通知回収用SSH接続がなくても、Orcaの画面で作業の応答終了を確認した後、同じタブに読み取り専用の判定ペインを作成します。判定AIにはTASKの指示・完了条件・報告書パスを渡し、成果物の確認を依頼します。

TaskDeskは判定要求ID・TASK ID・開始終了マーカーを含むJSONを、同一端末の終了状態と安定した画面から回収します。全条件に達成の根拠がある場合だけ次TASKへ進みます。結果欠落・不一致・タイムアウト・作業再開時は要確認で停止します。ペイン作成の応答が失われても自動で再作成しません。

補助検証スクリプトを有効にしている場合、画面回収方式だけではそのスクリプトの終了コードを検証できないため、要確認になります。通知方式は引き続き利用できます。手動進行設定とClaudeの既存動作は維持します。更新前から動いているワーカーにはこの変更は適用されません。
