# TaskDesk

タスクをツリーとして整理し、Codex / Claude Code に順次実行させるローカル Web アプリです。

上部の横スクロール一覧でツリーを切り替え、メイン画面では WP ごとに TASK を表示します。TASK をクリックすると、画面中央でプロンプト・作業マシン・作業ディレクトリ・AI ツール・モデル名・Thinking・Approve を設定できます。日本語 UI、データの永続保存、SSH マシンへの実行委譲に対応しています。

## 起動

必要環境: **Node.js 22 以降**、実行するマシンにインストール・ログイン済みの **Codex CLI または Claude Code CLI**。実行時の追加 npm パッケージはありません。

```powershell
cd C:\Users\yuki-\.vscode\Python\TaskDesk
npm.cmd start
```

ブラウザで **http://localhost:4317** を開きます。macOS / Linux では `npm start` を使用します。

ターミナルを閉じても Web サーバーを動かす場合:

```powershell
npm.cmd run background
npm.cmd run stop
```

コード更新後にバックグラウンドサーバーへ反映する場合は `npm run restart`（Windowsは `npm.cmd run restart`）を実行します。`npm run herdr` で「起動中のサーバーが旧バージョン」と表示された場合も同じです。`npm start` で起動したサーバーは元のターミナルで Ctrl+C を押してから `npm run background` で起動し直してください。

`stop` は Web サーバーだけを停止します。実行中のタスクは独立したワーカーで継続します。**タスクの停止は画面の「停止」から**行ってください。

ポートと保存先は `PORT` / `WORK_TREE_DATA` 環境変数で変更できます。同じ保存先のサーバーを二重起動することはできません。

### localhost 限定のアクセス

- Web 画面と API は、この PC のループバックアドレス `127.0.0.1` に固定して待ち受けます。`localhost` も同じ PC を指します。LAN・インターネット向けのアドレスや `0.0.0.0` では待ち受けません。
- 接続元アドレス、Host の名前とポート、Origin を検証します。別ドメインや別ポートからのアクセスを拒否し、転送ヘッダーをアクセス許可の根拠には使用しません。
- 外部ページから API を呼び出すアクセスを拒否します。リンクから公開の入口ページ `/` を開く操作は許可します。
- 設定変更・実行開始には、引き続き同一 origin のセッショントークンが必要です。同じ PC 上の他プロセスとの分離やユーザー認証を行う仕組みではありません。

localhost 限定は **Web 画面・API の公開範囲**です。AI 実行時の AI サービスへの通信や、選択した SSH マシンへの通信は別途発生します。完全オフライン実行を意味するものではありません。

## 最初の操作

1. 右上の「設定」→「マシンと AI ツール」から **接続・CLI 確認**を行います。
2. 「ワークツリー作成」に、目的・現状・想定タスクフロー・完了条件・制約を入力します。「実行の既定設定」でツリー名、実行先、AI、マシン、作業ディレクトリ、常駐マシン、制限時間、CLI 詳細・MCP・添付を設定できます。Orca の場合はプロジェクト・ホスト・ワークツリーを指定します。設定は作成後のツリーにも保存されます。
3. 作成が完了するとツリーを自動で取り込みます。上部の計画作成状況・ログ一覧は表示しません。生成には CLI を利用し、入力した5項目はツリーにも保存します。
4. 「ツリー編集」でメイン画面の名前を直接編集し、ドラッグで配置・順番を変更します。WP / TASK の追加・削除、詳細内のプロンプト・完了条件・依存関係も編集できます。「編集を完了」で保存します。
5. TASK をクリックして実行設定を確認し、「タスク実行」を押します。変更は実行前に保存します。編集だけの場合は `Ctrl+S`、またはメイン画面の「変更を保存」を使用します。
6. 上部の「次WPを実行」「次TASKを実行」は、表示中の次の実行対象を開始します。依存先が完了した未完了 TASK を配置順に選び、その親 WP を次WPとします。同じリビジョンの完了済み依存タスクは再実行しません。「ツリーを実行」は全体の実行です。ツリーを編集・保存すると新しいリビジョンになるため、以前の結果を完了判定には使いません。

画面は `design/work-tree.pdf` / `design/work-tree.pptx` の3画面を基にしています。同じ依存段階の TASK は横に並べ、WP は縦に表示します。横並びは依存関係の分岐を表し、実行は従来どおり順次です。TASK カードは番号・名前・状態だけを表示し、ツール名と依存先の説明を省いて高さを抑えています。AI 編集は範囲を選んで案を確認・適用できます。エラー・想定外結果の場合も同じ仕組みで見直します。

最初のサンプルは未実行です。作業ディレクトリを設定するまで実行できません。

## Orca からタスクを実行する

「ツリー編集」→「実行の既定設定」で **Orca の対話 Agent** を選び、Orca のプロジェクト・ホスト・ワークツリーを指定します。TASK ごとに実行先を上書きでき、ローカルと SSH サーバーの作業を同じツリーにまとめられます。タスク専用タブで Codex / Claude Code を起動し、モデル・思考量・承認設定とプロンプトを渡します。

Orca 上の Codex 終了通知を回収し、TASK に設定した検証結果からラベルを記録します。検証未設定の場合は確認待ちです。[終了通知と自動完了](docs/notifications.md) を参照してください。TaskDesk と Orca は同じ PC・ユーザーで起動してください。詳しい手順と対応範囲は [Orca 連携](docs/orca-integration.md) を参照してください。

## herdr からタスクツリーを使う

Webのノード実行をherdrへ委譲し、**Space＝ツリー名、Agentの表示名＝ノード名**として表示できます。[herdr ノード実行・命名設計](docs/herdr-execution-design.md) に実装上の対応と制限を記載しています。

herdr のターミナル内（WSL / Linux / macOS）で実行します。Node.js 22 以降が必要です。追加 npm パッケージや herdr 本体の改造は不要です。

```bash
cd /mnt/c/Users/yuki-/.vscode/Python/TaskDesk
npm run herdr
```

TaskDesk サーバーが未起動ならバックグラウンドで起動し、登録済みの各ツリーに対応するSpaceと管理タブを作成・再利用します。そのツリーの実行先をherdrに設定します。`npm run herdr -- --tree <ツリーID>` で対象を限定、`--session <名前>` でherdrの接続セッション、`--focus` で表示するSpaceを指定できます。旧 `--down` は互換性のため受け付けますが、分割方向には使用しません。Spaceを開いた時点ではAIを起動しません。

Web画面の「ツリー編集」→「実行の既定設定」→「実行先」で **herdr の Agents で実行**を選択することもできます。ノードを選び、中央画面の **タスク実行** を押すと、依存先を含む実行タスクをノード専用ペインで順に実行します。グループは子孫のタスクを実行します。名前を編集・保存すると対応するSpace／Agentの表示も更新し、同名の項目は短い識別子で区別します。送信先は名前ではなく永続化したIDと所有マーカー、対話CLIの前面プロセスグループIDで検証します。

各ペインでネイティブの対話 Codex／Claude Code を、モデル・思考量・承認設定を付けて起動します。起動と入力待ちを確認してから `herdr agent prompt` でノードのプロンプトを送ります。追加の会話や承認への回答は herdr で行えます。AI が入力待ちになったら TaskDesk の「結果を記録」で結果ラベルと要約を入力してください。「完了」なら後続 TASK へ進み、「エラー」「想定外結果」なら後続を止めて編集案を作成します。待機状態だけでは自動完了にしません。完了後も会話は残り、再実行時は前回の会話が開いていれば新しいペインを作成します。ゴールの自動反復は対話実行では使用できません。

ローカルの作業ディレクトリは開始前に存在を確認します。WSL 上では `C:\Users\…` を `/mnt/c/Users/…` に変換して実行します（標準の `/mnt/<drive>` マウント）。保存済みの計画は元のパスを保持し、実行履歴には変換後のパスを残します。SSH のパスは変換しません。

対応範囲は **TaskDesk・herdrが同じWSL / Linux / macOS環境で動くローカル実行**です。実行管理マシンと各ノードのマシンを「このマシン」にしてください。Web の実行設定で通常実行・herdr・Orca を選択できます。herdr実行でのリモートマシン指定は送信前に拒否します。

現在のターミナルで管理画面を開くなら `npm run tui`。herdr外でも使用できます。`npm run herdr` で開く管理タブは、個々のノードのAgent表示と重複しないよう全体のAgent通知を行いません。単独の `npm run tui` は従来の全体通知を行い、`--no-report` で無効にできます。管理画面やWebサーバーを閉じても独立した実行ワーカーは継続します。実行中のノードペイン／Spaceを閉じる操作は、対話CLIを終了させるため避け、TaskDeskの「停止」を使用してください。

画面内の操作:

| 操作 | キー／コマンド |
| --- | --- |
| ノード選択 | ↑↓ または j / k |
| ツリー切替 | ←→ または h / l、Tab |
| ノード詳細 | Enter |
| 詳細・結果のスクロール | PageUp / PageDown |
| コマンド入力 | `:` を押して入力し、Enter で送信。Esc で中止 |
| 操作一覧 | `?` または `:help` |
| ツリー作成 | `:new 開発計画 \| /home/user/project`（実際の入力では `\|` ではなく `|`） |
| グループ／タスク追加 | `:group 実装` / `:add テストを書く` |
| ノード編集 | `:rename 名前` / `:prompt 実行する指示` / `:criteria 完了条件` |
| ツリーの既定値 | `:cwd /home/user/project` / `:tool codex` / `:tool claude` |
| 親・順序・依存先 | `:move 2` / `:move root` / `:up` / `:down` / `:deps 1,3` / `:deps none` |
| 実行後に確認 | `:review on` / `:review off` |
| 選択ノード／グループを実行 | `:run`（必要な依存先も毎回実行） |
| ツリー全体を実行 | `:run-tree` |
| 前回の全体実行の未完了部分から | `:continue` |
| 実行制御 | `:pause` / `:resume` / `:stop` / `:approve` |
| 履歴・結果 | `:history` / `:history 1` / `:result` / `:log` |
| 選択タスクへ追加依頼 | `:chat 修正してほしい内容` |
| Web 画面の URL | `:web` |
| 画面を閉じる | q または Ctrl+C（タスクは継続） |

`move` / `deps` は画面に表示されるノードの行番号で指定します。グループを選択して追加するとその子に、それ以外では同階層に追加します。`prompt` / `criteria` 内の `\n` は改行になります。添付、モデル・MCP・SSH の詳細設定、削除は引き続き Web 画面で操作できます。herdr 本体のサイドバーにツリー編集メニューを追加する構成ではなく、分割ペイン内の専用画面で操作する連携です。

**ノード実行の範囲:** 選択したタスク（グループなら子孫のタスク）と、その依存先を再帰的に含めます。親グループの共通指示、ノード別 CLI 設定、確認待ちを維持します。無関係な兄弟タスクは実行しません。依存先が過去に成功していても再実行します。履歴は「ノード実行」として Web と共有し、全体実行の「続きから」の基準にはしません。`:run` / `:run-tree` / `:chat` は入力直後に AI の実行を開始します。

接続先は既定で `http://127.0.0.1:4317` です。`PORT` / `WORK_TREE_DATA` はサーバー起動設定、`WORK_TREE_URL` は既存サーバーへの明示的な接続先です。例:

```bash
WORK_TREE_URL=http://127.0.0.1:4318 npm run herdr
npm run tui -- --url http://127.0.0.1:4317 --once
```

同じ API・セッショントークン・編集競合チェックを使用します。ローカルアドレスだけに接続し、LAN 向けに公開しません。旧バージョンの Web サーバーが動作中なら、起動元の環境で停止してから更新後のサーバーを起動してください。**Windows と WSL から同じ保存先のサーバーを同時起動しないでください。** Windows 側で稼働中の場合は元のターミナルでサーバーを終了してから WSL 側で起動します。保存済みの Windows 作業パス／CLI パスは WSL 用パスへ設定し直す必要があります。WSL から Windows の localhost に接続できない場合も、アクセス制限を緩めず TaskDesk と herdr を同じ環境で動かしてください。

API では `POST /api/trees/<treeId>/run` の JSON に `{ "nodeId": "対象ID" }` を指定します。`resume` との同時指定はできません。通常の `{}` / `{ "resume": true }` は従来どおり全体実行です。

2026-09-20: herdr 0.9.1 / WSL の実ペインで、Codex／Claude 名のテスト用対話 CLI を使用し、設定付き起動、複数行の入力、明示的な完了確定、依存先の結果引き継ぎ、会話保持、再実行時の新規ペイン、停止を確認しました。実際の AI サービス・SSH 接続はこの検証には含みません。

この実機テストはherdr内で `npm run test:herdr` により再実行できます。一時Spaceと `.test-data/` 内の隔離データ、C コンパイラーで作成したテスト用CLIを使用し、終了時に作成したSpaceを閉じます。通常の `npm test` はherdrを操作しません。

### 「Could not find home directory」で計画生成が失敗する場合

Web サーバーを Codex の制限付き実行ユーザーなど、ユーザープロファイルを利用できない環境から起動すると、その環境を引き継いだ Codex CLI がホームを解決できずに失敗します。`USERPROFILE` の文字列が通常ユーザーのパスでも、実際の OS 実行ユーザーが同じとは限りません。

**Codex にログインした通常ユーザーの PowerShell** で以下を実行します。管理者としての起動は不要です。

```powershell
cd C:\Users\yuki-\.vscode\Python\TaskDesk
npm.cmd run stop
npm.cmd run doctor
npm.cmd run background
```

`doctor` は OS の実行ユーザー・ホーム・CLI のバージョン・`codex login status` を確認します。Codex が未ログインの場合は、同じ PowerShell で `codex login` を行ってから再起動してください。認証ファイルの内容は読み出し・表示しません。

起動時に OS のユーザープロファイル取得を検証し、取得できない環境では説明付きで停止します。別ユーザーの `HOME` / `CODEX_HOME` の強制指定や認証情報のコピーで回避することはありません。バージョン確認時の標準エラーも検査するため、「バージョンだけは取得できるがホームは取得できない」状態も検出します。

## タスクツリー

- **グループ**: 子ノードを整理するためのノード。共通プロンプトを子孫のタスクに渡します。グループ自身は実行しません。
- **実行タスク**: 末端ノード。プロンプト、完了条件、AI ツール、モデル、マシン、作業ディレクトリ、環境変数、実行権限、依存先、確認待ちを設定できます。
- 「ツリー編集」で画面上の WP / TASK を直接改名・追加・削除できます。WP を削除すると子ノードも削除します。
- ドラッグで移動・並べ替えできます。「詳細」の配置先・上下ボタンでも操作できます。
- 親子関係と依存関係は別々に保持します。依存関係を満たす末端ノードを、ツリーの表示順（深さ優先）で一つずつ実行します。
- 先行タスクの結果と祖先グループのプロンプトを後続タスクに渡します。結果の引き継ぎは直近最大 12 タスク、各結果末尾 10,000 文字です。
- 循環、存在しない親、重複 ID、不正なマシン指定を検証します。上限は 300 ノード・16 階層です。
- AI が生成できる項目は計画に限定しています。AI 出力から実行マシン・環境変数・権限を勝手に設定しません。

**「完了」の意味:** herdr 対話実行は、入力待ちの Agent の成果物を人が確認し、結果の要約を入力して完了を確定した状態です。この確認が従来の実行後レビューも兼ねます。非対話バックエンドでは CLI の正常終了と最終回答の取得を意味し、任意のレビューを設定できます。

## ツリー編集と試行錯誤

WP の見出しにある ↑ / ↓ で順序を変更できます。ドラッグ中は挿入位置に線が表示され、画面の上端・下端へ近づけると自動スクロールします。WP の本文へのドロップは並べ替え、「この WP に移動」の領域へのドロップは配下への移動です。詳細の配置先・上下ボタンでも操作できます。

「ツリー編集」→「AI で編集」では、全体または指定した WP / TASK を選び、変更指示を入力します。WP を選ぶと配下も対象です。現在の編集を保存し、選択した対象のモデル・思考量を使って編集案を作成します。ファイル編集は行わない計画用の非対話 CLI を使い、ノード実行は従来どおり herdr の対話モードを使います。

編集案には理由と変更前後を表示します。「この案で編集する」で保存し、「編集しない」で見送ります。AI はプロンプト・完了条件・構造・順序を変更でき、モデル・環境変数・権限などの実行設定は変更できません。編集範囲外の変更、親子／依存関係の循環、存在しない参照は拒否します。生成中にツリーや対象の実行結果が変わった案は、再生成が必要です。

TASK の結果は **完了 / エラー / 想定外結果** のラベルで保存します。Orca の Codex では終了通知と事前設定した検証に基づいて付与し、herdr では「結果を記録」で選択します。CLI 自体の異常終了はエラーになります。完了以外の場合は後続を実行せず、その TASK と依存する後続 TASK の編集案を自動生成して TASK の下に表示します。結果を記録した TASK の ID は維持します。案の適用・見送り・生成失敗は保存され、ページやサーバーを再起動しても重複生成しません。生成に失敗した場合は、原因を修正して「編集案を再生成」を押せます。過去の実行へ遡って自動生成は行いません。

案を適用してもタスクは自動実行しません。編集内容を確認し、対象 TASK / WP / ツリーを実行してください。以前の結果は履歴に残り、編集後のカードには「前回」として表示します。

## 一時停止・停止・再開

- **一時停止**: 現在のタスクを完了させてから停止します。確認待ちは維持します。
- **停止**: 実行中の CLI を停止し、後続タスクを開始しません。既に編集されたファイルは元に戻しません。
- **続きから**: 直前の実行で成功したタスクを再利用し、未完了タスクから新しい実行を開始します。途中まで変更されたファイルを確認してから再実行してください。
- ツリーを編集すると revision が更新されます。編集前の実行は履歴に残り、編集後は最初から実行します。
- 実行中・確認待ち・一時停止中のツリーは編集できません。
- 同じマシン ID・作業ディレクトリを使うツリーの同時実行を抑止します。別名の SSH 設定やシンボリックリンクまでは同一判定できないため、実際に同じ作業領域を共有しないようにしてください。

## PC を閉じても実行を続ける

| 状況 | 動作 |
| --- | --- |
| ブラウザを閉じる | ローカル・SSH とも実行継続 |
| TaskDesk の Web サーバーを終了 | 独立した実行ワーカーは継続 |
| 手元の PC をスリープ・シャットダウン | ローカルの処理は継続できません |
| ツリー全体を常時稼働 SSH マシンに委譲 | 手元の PC が停止しても接続先で次のタスクへ進みます |
| 実行管理マシン自体が再起動・停止 | 実行は中断。自動でタスクを再投入せず、確認後に再実行します |

### SSH セットアップ

接続先は **Linux / macOS、Node.js 22 以降**を想定しています。Windows SSH サーバーは現在対象外です。

1. 通常のターミナルで `ssh user@host` が成功するように、鍵認証と `known_hosts` を設定してください。TaskDesk は `BatchMode=yes` と `StrictHostKeyChecking=yes` を使います。パスワード入力や未知のホスト鍵への応答は行いません。
2. 接続先に Node.js と必要な AI CLI をインストールし、そのユーザーでログインしてください。TaskDesk が認証情報を転送することはありません。
3. 作業対象のリポジトリを接続先に用意します。Git の clone / checkout やファイル同期は自動実行しません。
4. 画面の「マシンと AI ツール」→「SSH マシンを追加」。SSH config の Host 名または `user@host`、ポート、実行ファイルのパスを指定します。`~` や `$HOME` を含む実行パスはシェル展開しないため、絶対パスを指定してください。
5. 「接続・CLI 確認」で接続を確かめます。CLI のバージョン検出はログイン成功や実行権限を保証するものではありません。
6. ツリーの「実行設定」で **既定の実行マシン**と **実行管理を常駐させるマシン**の両方に SSH マシンを指定します。作業ディレクトリも接続先のパスにします。
7. ノード側に「このマシン」の上書きがないことを確認し、実行します。

ツリーのスナップショットと小さな Node.js ワーカーを接続先の `~/.work-tree/runs/<実行ID>/` に転送します。ワーカーは SSH 接続から独立して起動し、接続が切れても順次実行します。手元で TaskDesk を再度開くと状態を取得します。

複数の SSH マシンをノード単位で混在させる場合、**実行管理マシンから各接続先への SSH 接続**が必要です。SSH の Host 設定・鍵・実行パスは実行管理マシンから見た設定になります。手元の SSH agent forwarding は自動で有効にしません。

実行管理をローカルのままにしてノードだけを SSH にした場合、開始済みのリモートタスクは継続しますが、手元の PC のスリープ中には次のノードへ進みません。継続実行が必要な場合はツリー全体を SSH に委譲してください。

SSH 通信が途切れた場合は最終取得時点の状態を表示し、同じタスクを重複投入しません。接続が戻るまで状態取得・停止指示ができません。リモート実行の確認待ちで手元を閉じた場合は、確認されるまでそこで待機します。

## 実行権限とデータ

- Codex: `codex exec --json --sandbox workspace-write -`、または `read-only`。
- Claude Code: `claude -p --output-format stream-json --verbose --permission-mode acceptEdits`、または `plan` / `dontAsk`。
- プロンプトは標準入力で渡し、ローカルではシェルを介してコマンドを実行しません。Windows の npm shim は JS エントリに解決します。
- 既存の CLI 認証・設定を利用します。既定では Codex は `workspace-write` + `approval_policy=never`、Claude Code は `acceptEdits` です。全アクセス／権限確認スキップは、CLI 設定で明示的に選んだ場合だけ適用します。CLI の途中の承認要求に画面から回答する機能はありません。
- ノードの環境変数とプロンプトは保存先に平文で記録されます。通常の API キーは実行マシンの CLI 認証・環境で管理してください。
- データは `.work-tree/`、リモート実行データは接続先 `~/.work-tree/runs/`。Git の管理対象から除外しています。
- Node.js の JSON ファイルへの書き込みは一時ファイルからの rename で行います。編集競合は revision で検出します。
- 画面の編集には同一 origin とセッショントークンを要求します。個人用ローカルアプリとして設計しており、インターネットに直接公開する構成ではありません。
- 実行履歴を保持します。ログは実行ごと約 12 MB、画面での取得は末尾 64 KB に制限しています。古い履歴の自動削除・秘密情報の自動マスキングはありません。

## CLI ごとの設定

「実行設定」にツリー全体の既定値を設定します。ノードの「モデル・思考量・承認・モード・添付・MCP」から「このノードで上書きする」を有効にすると、CLI ごとに上書きできます。「ノードに反映」のあと「変更を保存」を押してください。Codex と Claude Code の設定は独立して保持します。既存のノードに設定済みのモデル・読み取り専用権限も保持します。

| 項目 | Codex | Claude Code |
| --- | --- | --- |
| モデル | ローカル CLI のモデルキャッシュから候補表示・直接入力 | sonnet / opus / haiku・直接入力 |
| 思考量 | minimal / low / medium / high / xhigh / max / ultra | low / medium / high / xhigh / max / ultracode |
| 承認 | 追加承認なし・自動承認レビュー | default / acceptEdits / plan / dontAsk / auto / bypassPermissions |
| 実行範囲 | read-only / workspace-write / danger-full-access | 権限モード・許可／禁止ツール |
| その他 | プロファイル・Web 検索・追加ディレクトリ | 追加ディレクトリ |
| MCP | `mcp_servers` を JSON で指定し TOML に変換 | `mcpServers` を一時 JSON ファイルとして渡す・strict モード |

空のモデル・思考量は CLI の既定値です。候補は利用権限を保証しません。SSH 先や古い CLI では対応するモデル・思考量・フラグが異なります。Codex の max / ultra は、この PC の 0.154.0 のモデルキャッシュに基づきます。Codex の自動承認レビューは workspace-write と組み合わせます。未対応の値は CLI のエラーを実行ログに表示します。

### 実行モード

- **通常実行**: 1 回の CLI 実行結果をノードの成果として保存します。
- **プランニング**: 計画・調査を指示し、Codex は read-only + never、Claude Code は plan を優先します。追加の作業ディレクトリ権限は渡しません。「AI と計画をつくる」もこのモードで実行し、取り込み後のツリーには選択した既定値を引き継ぎます。
- **ゴール**: TaskDesk が実行と完了確認を反復するモードです。CLI ネイティブの `/goal` や会話再開とは別の機能です。各回は新しい CLI セッションで、元の指示・完了条件・前回の最終結果を渡します。ファイルの変更は同じ作業ディレクトリに保持します。構造化した回答の `completed=true` と空でない検証根拠を確認して終了します。判定は AI の自己申告なので、必要なノードには実行後の人の確認も設定してください。最大 1〜20 回（既定 3 回）、合計時間はツリーの制限時間以内。未達成・不正な結果は失敗とし、自動で次のノードへ進めません。

上記のゴール自動反復は非対話バックエンド向けです。herdr 対話実行では通常／プランニングを使用し、会話・質問・承認は herdr で操作します。非対話バックエンドでは途中の質問・承認やスラッシュコマンドは利用できません。Codex は `never` で権限外の操作を拒否します。Claude Code では許可ツールを事前設定できます。ノードの「実行後に人が確認」は、CLI のコマンド承認とは独立した確認ゲートです。

### 添付ファイルと MCP

ツリーとノードの添付を合わせて AI に渡します。アップロードは 1 ファイル 5 MB、各設定 20 個、実行全体で 20 MB まで。ファイル名を保存パスに使用せず、生成した ID で `.work-tree/attachments/` に保存します。実行開始時のスナップショットにデータを固定し、SSH ワーカーにも転送します。非対話実行では展開したファイルを CLI 終了後に削除します。herdr 対話実行では継続する会話から参照できるよう実行ディレクトリ内に保持します。元のアップロードと実行スナップショットは履歴として保持し、自動削除はしません。

画像は Codex の `--image` に渡します。その他の資料と Claude Code の添付は、パスをプロンプトへ記載して Read 等のツールで参照します。形式によって CLI 側の読み取りツールが必要です。「実行先にあるファイル」に入力したパスは転送せず、その実行マシンの既存ファイルを参照します。

MCP は既存の CLI 設定を読み込み、入力した同名サーバーの設定で上書きします。空の `{}` は既存設定の継承です。Codex は `{ "serverName": { "enabled": false } }` で既存サーバーを無効化できます。Claude Code は strict を有効にすると指定した MCP 設定だけを使います（組織の管理設定が優先される場合があります）。OAuth の初回ログインは実行マシンの CLI で行ってください。MCP のコマンド・パス・認証環境も実行マシン側を使用します。

MCP の外部サービスへの変更はファイルのサンドボックスでは制限されません。計画モードでも、変更機能を持つ MCP には必要に応じてサーバー側の読み取り権限を設定してください。入力した MCP 設定と環境変数は平文保存されます。

設定の対応は [OpenAI 公式 Configuration Reference](https://learn.chatgpt.com/docs/config-file/config-reference)、インストール済み `codex exec --help`、[Claude Code CLI reference](https://code.claude.com/docs/en/cli-reference) に基づきます。

### ノードの設定と実行履歴

TASK の中央画面では、プロンプト、作業マシン、作業ディレクトリ、AI ツール、モデル名、Thinking、Approve を順に設定します。表示値にはツリーの既定値とノードの上書きを合成します。既存の CLI 詳細設定も保存時に維持します。WP 実行には子 TASK ごとの設定を使用します。

下部の「タスク実行」は設定を保存してから送信し、連打による二重実行を防ぎます。herdr の専用ペインで設定付きの対話 CLI を起動し、Agent の識別と入力待ちを確認してからプロンプトを1度だけ送信します。起動引数を実行ログへ記録し、MCP 設定値は伏せます。モデル・Thinking が空欄の場合は実行先 CLI の既定値です。

herdr セッションと既定設定は「ツリー編集」→「実行の既定設定」にあります。Space＝ツリー名、Agent の表示名＝ノード名です。Web からの実行はローカル herdr を使用します。

「実行履歴」から過去の実行ログとタスクごとの結果を確認できます。設定画面は × または Escape で閉じます。チャット画面は使用しませんが、過去の履歴・公開イベントと追加依頼 API は保持しています。

ブラウザーの動作確認用に `node scripts/ui-smoke.cjs` を用意しています。Playwright と Chromium を別途用意し、必要に応じて `WORK_TREE_PLAYWRIGHT` に `@playwright/test` のパッケージパス、`PLAYWRIGHT_BROWSERS_PATH` にブラウザーの配置先を指定してください。隔離データとテスト用 CLI で保存・実行・エラー表示・二重送信防止・モバイル表示を確認します。

### Notion 連携

1. Notion で内部コネクションを用意し、「コンテンツを読み取る・挿入する・更新する」を許可します。保存先ページの接続メニューからそのコネクションを追加します。
2. 右上「設定」→「Notion 連携」を開き、トークンを入力します。チャットへの貼り付けは不要です。代わりにサーバー起動時の環境変数 `NOTION_TOKEN` も利用できます。
3. 親ページ URL を確認し、「専用データベースを作成」を押します。今回指定された `app.notion.com` URL は、クエリーの `p=3dfc4f28d28480f9b020c1f92d5c2314` を保存先ページとして初期設定しています。共有権限とページの内容は、認証後に確認してください。
4. 保存したいツリーを選び、「ツリーを Notion に保存」を押します。これがそのツリーの連携開始になります。既存の TaskDesk データベースに再接続する場合は **データソース ID** を入力します（データベース ID とは異なります）。

同期は Notion API `2025-09-03` を使い、CLI の MCP 設定とは独立しています。データベースには Tree／Group／Task／Result の行を作ります。`Name`、`Prompt`、`Criteria`、`Parent`（親ノード ID）、`Order`、`Dependencies`（カンマ区切りノード ID）を編集できます。`WT Key` と `Tree` は識別用なので変更しないでください。削除したいノードは `Removed` にチェックし、子・依存先も整合させてください。ノード ID は Task／Group 行の `WT Key` のツリー ID に続く部分です。

連携済みツリーは、実行前に最新の計画と直近 12 件の結果要約を取得し、開始時のスナップショットに固定します。Notion に接続できない場合や計画に循環・欠落がある場合は開始しません。ローカルの計画に変更があれば先に保存を求め、両側の編集が競合すると上書きを止めます。「Notion から取得」の置き換えチェックを選ぶと、ローカルの計画変更を明示的に破棄できます。CLI 設定・環境変数・実行先・添付・MCP 設定はローカルで保持し、Notion から変更しません。

連携開始後の各タスクの完了・失敗・停止結果は自動保存します。Result 列は末尾 12,000 文字の要約用データ、ページ本文には依頼と結果全文を保存します。過去の結果を取得しても、未実行タスクを自動的に完了扱いにはしません。同期失敗時は永続キューから再試行し、Web サーバー停止中の結果も再起動後に送信します。SSH 常駐実行は PC を閉じても続きますが、Notion 同期は TaskDesk サーバーが動作して SSH に接続できる間に行われます。

トークンは `.work-tree/notion-settings.json` に平文保存され、API 応答・AI プロンプト・SSH の実行スナップショットには含めません。サーバーの `NOTION_TOKEN` はワーカーに引き継ぎません。保存ディレクトリは Git の対象外です。プロンプトや作業結果に自分で記載した情報は、その内容のまま Notion に同期されます。共有範囲は Notion 側のページ設定に従います。

仕様: [Notion データソースへの移行](https://developers.notion.com/docs/upgrade-guide-2025-09-03)、[データベースの作成](https://developers.notion.com/reference/create-a-database)、[API 制限](https://developers.notion.com/reference/request-limits)。

TaskDesk/

│  ├─ core.cjs            データ検証、依存関係、実行順
